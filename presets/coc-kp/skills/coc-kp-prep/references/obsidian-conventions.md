# 笔记规范（唯一权威）

`lint_notes.py` 逐条校验本文件里的**硬规则**。硬规则之外的内容风格自由，硬规则之内一字不改。

---

## 1. 目录

```
<仓库根>/
├── <模组名>.<ext>              ← 用户导入的原件，只读，永不改写
└── <模组名>/
    ├── 总览.md
    ├── 场景/<场景名>.md
    ├── 角色与势力/
    │   ├── NPC/<NPC名>.md
    │   └── 调查员/_README.md      ← 只此一个文件
    ├── 素材/
    │   ├── 场景/<与场景笔记同名>.md
    │   ├── 线索/<线索名>.md
    │   └── 立绘/<与 NPC 笔记同名>.md
    └── .meta/
        ├── source.txt  outline.md  glossary.md  manifest.md  lint-report.txt
```

## 2. 命名

| 对象 | 规则 |
|---|---|
| 模组名 | = 原件文件名去扩展名（`快乐王子.pdf` → `快乐王子`） |
| 笔记基名 | **纯名字，不加序号**（`德莱尼子爵府.md`）。序号会让 `[[德莱尼子爵府]]` 在 Obsidian「最短路径」设置下解析失败 |
| 链接目标 | `[[基名]]`，与文件名逐字一致 |
| tag 里的模组名 | slug 化：空格→`-`；去掉 `#` `[` `]` `/` `\|` `:`；首字符不能是数字 |
| 场景顺序 | 有 `date` 按时间排，否则按源文出现顺序；只写在 `总览.md`，不写进文件名 |

## 3. 场景笔记

### 3.1 frontmatter（属性顺序固定）

```yaml
---
tags:
  - TRPG
  - COC
  - "#快乐王子"
  - "#场景"
date: 1891-09-30T10:00:00
地点: 伦敦海德公园附近，德莱尼子爵府邸
天气: 秋雨初歇，薄雾未散，空气中弥漫着潮湿的寒意
人物:
  - "[[埃尔文·琼斯]]"
  - "[[大卫·霍华德]]"
  - "[[玛丽]]"
---
```

- `tags` **恰好四项、顺序固定**：`TRPG`、`COC`、`"#<模组名>"`、`"#场景"`。后两项带引号。
- `date` 格式 `YYYY-MM-DDTHH:MM:SS`。模组没给日期就**整行省略**。
- `地点`：**自由文本**，可带修饰语，**不加** `[[ ]]`。
- `天气`：一句话，暗示氛围。模组没写时可写与该场景基调一致的合理天气，**不得引入新设定**。
- `人物`：`[[NPC名]]` 列表，只列该场景**实际出场**的人（有台词、或调查员可能交谈）；每个都必须有对应 NPC 笔记。
- 不新增其他属性（不要 `aliases`、`cssclasses`、`来源` 等）。

### 3.2 正文骨架

```
## <空间/地点 A>
<环境描写：调查员视角，「你们」为主>
### <此处的互动物 / 证言 / 次空间>
> [!success] <技能>成功
> <结果>
## <空间/地点 B>
…
### <分支：调查员可能的选择>
<该分支下会发生什么>
```

- `##` 用于空间/地点，`###` 用于互动物、证言、分支。**不出现 `#` 一级标题**（笔记标题即文件名）。
- 空间顺序 = 玩家会走动的顺序，先「外面看到什么」，再「进去看到什么」，再「下一步去哪」。
- 日记、信件、证言、NPC 原话：**引号原文照录，逐字不改**，可以用引用块。
- 不写「时间线」「战斗数据」「守秘人备忘」这类附加区块。

### 3.2.1 篇幅与文体硬指标（lint 会检查，不达标必须重写）

| 指标 | 硬指标（lint 报 WARN 即视为不合格） | 目标 |
|---|---|---|
| 场景笔记正文汉字数 | ≥ 700 | 1200~3000 |
| 场景笔记叙述段落数（≥60 汉字的散文段） | ≥ 3 | 8~15 |
| NPC 笔记正文汉字数 | ≥ 500 | 900~2500 |
| NPC 笔记叙述段落数 | ≥ 3 | 6~15 |
| 正文破折号「——」 | 每千汉字 ≤ 2 处 | 0 处 |
| 「不是…是/而是」类对照句 | 每千汉字 ≤ 2 处 | 0 处 |

数值门槛是**底线**，不是目标：交付标准是场景 ≥1200 汉字、NPC ≥900 汉字。
文风、句式禁令与写法见 `style.md`。
**风格与判断**见 §0、§5、§7。

### 3.3 callout 硬规则

```markdown
> [!success] 侦查成功
> 草地上有几处颜色深浅不一的地方，走近之后，你发现那是几处靴印。

> [!fail] 估价失败
> 失败后的特别结果（只有「失败本身会产生特别事件」时才写这一条）。

> [!tip] 需要提前定的事
> 非检定的提示：管家该住在哪、某段背景怎么处理。
```

1. **感叹号后必须有一个空格**：`> [!success] …`。`>[!success]` 判 FATAL。
2. 类型只有 `success` / `fail` / `tip` 三种。
3. `[!success]`、`[!fail]` 的标题含「成功」「失败」字样，技能名照模组原文（`侦查`、`聆听`、`估价`、`会计/伪造`、`交涉技能极难` …）。
4. `[!fail]` 是**例外**：只在失败会产生特别事件时写，**不与每个 `[!success]` 成对出现**。
5. 连续多条 callout 之间空一行。
6. callout 是**可选**的：一场戏没有可检定的互动就不写。

## 3.4 场景里不写 NPC 对白：用块引用嵌入

**场景笔记里不出现 NPC 的台词。** 对白写在 NPC 笔记里，场景用块引用把它引过来，
改台词只改一处，场景自动跟着变。

### 写法：一段对白一个块 ID

**每一段对白单独成段，在段落末尾内联一个块 ID**，
格式照插件生成的来：**一个短随机串**（4~7 位字母数字），例如 `^k7f2`、`^m3qp`。
按出场顺序编号也可以，但**编号要连写**：`^hu01`、`^hu02`、`^hu03`。
每段之后留一个空行：

```markdown
### 调查员问起夫人的病情

「夫人从月初就病着，不见客。」^hu01

「看诊是镇上的医生，来过几次，只他一个进过那间屋子。」^hu02
```

场景里逐段引人，只写引用，不写台词：

```markdown
### 询问管家

管家站在茶几旁，双手交叠在身前，答话时先看一眼门口。

![[管家#^hu01]]

![[管家#^hu02]]
```

### 最重要的一条：标记前必须有空格

**中文标点或汉字与 `^` 之间必须有一个空格。**

```markdown
「夫人从月初就病着，不见客。」 ^hu01      ← 对
「夫人从月初就病着，不见客。」^hu01       ← 错，Obsidian 会报「未找到 ^hu01」
```

原因：英文单词结尾时 `text^id` 能被解析，但**全角字符（汉字、。、「」）与 `^` 紧贴时解析失败**。
插件自动生成 ID 时会替你补上这个空格，手写时极易漏掉。这是实测确认过的失败原因，
也是「引用失败、原文被照抄出来」的最常见根因。

块 ID 后面**留一个空行**再写下一条内容。

### 其余三条建议

1. 块 ID 只用**一段字母数字**（`^hu01`、`^k7f2`），不要连字符；越短越不易出错。
2. **不要用 `^id-id` 范围写法**：它依赖插件的多行块设置，也容易因缺空格而整段失效。
   一段对白一个 ID，场景里逐段嵌入，最稳。
3. 一段对白在多个场景复用时**引用同一个 ID**，不要复制台词。

### 规则

1. **块 ID 前必须有空格**（中文标点后与 `^` 之间），linter 判 FATAL。
2. **场景笔记出现引号台词即判 FATAL**（模组原文照录的引用块除外，那些放在 `>` 引用块里）。
3. 块 ID 必须内联在行尾，**不得单独占一行**（linter 判 FATAL）。
4. 块 ID 必须唯一；一段对白在多个场景复用时**引用同一个 ID**，不要复制台词。
5. 场景里的 `![[X#^id]]` 必须在 X 笔记里确有其锚点（linter 判 FATAL）。
6. `^id-id` 范围写法与含连字符的 ID 会收到 WARN，建议按上面的写法改掉。
7. 场景需要一段 NPC 笔记里还没有的对白时，**先写进 NPC 笔记并打块 ID**，再从场景引用。
   台词永远只有 NPC 笔记这一个出处。

## 4. NPC 笔记

```yaml
---
tags:
  - TRPG
  - COC
  - 快乐王子
  - NPC
---
- **身份**：伦敦警察局总警督
- **外貌**：四十岁左右，英俊，三件套西装，自信。

## <场景名>
<他怎么出场、在做什么、对调查员的态度>

### <调查员可能问的话题 / 触发的局面>
<他的回应，用引号写原话；态度与潜台词写在动作与神态里>

#### <追问或施压后的分支>
> [!success] 交涉技能极难成功
> <他会说什么、做什么>

> [!fail] 交涉技能失败
> <失败的特别后果>
```

- frontmatter **只含 `tags`**；四项顺序 `TRPG / COC / <模组名> / NPC`，**前三项与 NPC 项都不带引号**（与场景笔记不同）。
- 正文**以两条分点开头**：`- **身份**：…`、`- **外貌**：…`。外貌要能被守秘人直接念给玩家听。
- `##` = 场景名（与场景笔记同名）；`###` = 话题/处境；`####` = 追问分支。
- 每个话题写成「玩家问 → 他答」。答案要**有模组依据**；模组没写的次要问题可在人设一致范围内补写，但**不得泄露模组指定的隐藏信息**。
- NPC 之间、NPC 与地点之间用普通 `[[链接]]` 交叉引用。
- v1 **不生成**块引用锚点与 `![[NPC#^锚点]]` 嵌入。

## 4.5 素材笔记（绘图提示词）

素材笔记**只写提示词**，不写设定说明。默认引擎 **Chat-GPT Image 2**，英文提示词 + 中文翻译。

```markdown
---
tags:
  - TRPG
  - COC
  - "#<模组名>"
  - "#素材"
  - "#线索"
---

## 提示词

<英文提示词，一段，可直接复制>

## 中文翻译

<对应中文，一段>

## 要点

- <必须出现什么、绝对不能出现什么>
```

- 后两个 tag 固定为 `"#素材"` 加类型：`"#场景"` / `"#线索"` / `"#立绘"`。
- **场景素材**（`素材/场景/`）：只画环境，提示词必须含 `no people, no figures, no silhouettes`；文件名与 `场景/` 下笔记同名。
- **线索素材**（`素材/线索/`）：模组里的笔记、信件、日记、告示、关键物品；提示词必须含 `transparent background`。
- **立绘素材**（`素材/立绘/`）：文件名与 `角色与势力/NPC/` 下笔记同名；外观**只依据该 NPC 笔记的 `- **外貌**：` 一行**；提示词必须含 `transparent background`。
- 纸面文字写 `illegible handwriting`，不要生成可读长文（会出乱码）。
- 三类都在**场景与 NPC 笔记全部写完之后**才动手。

## 6. `.meta/` 文件

| 文件 | 内容 |
|---|---|
| `source.txt` | 脚本产出：头部三行元信息 + `[[pN]]` 页标记 + 正文。**不要手改** |
| `outline.md` | 父产出：一张表（格式见 `pipeline.md`） |
| `glossary.md` | 父产出：`原名 → 唯一写法` 表 |
| `manifest.md` | 父产出：源文件与哈希、页数、抽取质量、清单与状态、跳过项、待人工确认 |
| `lint-report.txt` | 脚本产出 |

## 7. 常见错误（自查清单）

| ✗ 错 | ✓ 对 |
|---|---|
| `>[!success] 侦查成功` | `> [!success] 侦查成功` |
| `01-德莱尼子爵府.md` + `[[德莱尼子爵府]]` | `德莱尼子爵府.md` + `[[德莱尼子爵府]]` |
| `地点: "[[德莱尼子爵府]]"` | `地点: 伦敦海德公园附近，德莱尼子爵府邸` |
| 场景 tags 写 `#场景` | 写 `"#场景"`（带引号） |
| NPC tags 写 `"#NPC"` | 写 `NPC`（不带引号） |
| 每个 `[!success]` 都配一个 `[!fail]` | 失败没有特别事件就不写 `[!fail]` |
| `# 德莱尼子爵府` 一级标题 | 直接从 `##` 开始 |
| 把日记概括成「她在日记里提到宝石」 | 日记原文整段照录 |
| 素材笔记里写「这张图可以用来展示……」 | 只留提示词与中文翻译 |
| 立绘的外貌凭印象写 | 逐条对照 NPC 笔记的 `外貌` 行 |
| 线索/立绘漏了 `transparent background` | 两者都必须写 |
