# 场景笔记：站在调查员的位置描写

场景笔记的主体是**具体事物的描写**。调查员推门进来，眼睛看到什么、鼻子闻到什么、脚下踩着什么样、耳朵里有什么声音。写这些，写足。

叙述者始终**站在调查员的位置**。他们看不见的东西、模组里的真相、别人的心理活动，都不写进场景。

## 一、描写的是具体事物

- 写物件：材质、颜色、磨损、摆放、数量、干不干净。
- 写空间：多大、多高、光从哪来、往哪通、地面是什么、有没有回声。
- 写气味与温度：进门的第一个感觉往往是这两样。
- 写人：在场的人**在做什么**、穿什么、站在哪里、脸上是什么表情。
写人在做什么、穿什么、站在哪里、脸上是什么表情。**不要替他们说话**，台词一律从 NPC 笔记引过来（见下）。
- 写「不对劲」的那一处：一处就够，写准。不要写成五处。

✗「客厅布置得很讲究，透着一股压抑的气息。」
✓「两把坐塌了的布面沙发隔着一张矮茶几。北墙上挂着一幅装裱讲究的肖像，比屋里任何一件家具都气派。画像下方的墙纸上有一小块颜色略深，像是原本还挂着什么。」

## 二、按玩家走动的顺序推进

调查员是走进来的，所以按空间排：外面看到什么 → 推门进去 → 大厅 → 上楼 → 房间 → 出来遇到谁。

不要按时间线或剧情节点排。守秘人现场是按空间翻页的。

同一空间里的多件事用 `###` 分：某处的陈设、某件可检查的物、某段证言、某个分支。
**同一空间不要拆成多篇笔记**；换空间才换笔记。

## 三、对白从 NPC 笔记引过来

场景里**不写任何 NPC 台词**。对白写在 NPC 笔记里，场景用块引用嵌入：

```markdown
管家站在茶几旁，双手交叠在身前，答话时先看一眼门口。

![[管家#^hu-01-hu-01]]
```

这样改台词只改一处，场景自动跟着变。块 ID 的写法见 `obsidian-conventions.md` §3.4。

只有**模组原文照录**的材料（日记、信件、告示）留在场景里，用 `>` 引用块承载。

## 四、原文照录

日记、信件、电报、证言、印刷品、NPC 原话，**逐字保留**，包括错别字、断句、不配对的引号、删节号。
用引用块承载，并在它前后补一段环境，让读者顺势读到它。概括原文等于毁掉守秘人最有用的道具。

## 五、可检查的物写成 callout

每条 callout 对应玩家的一个动作：`我要检查地毯` → `[!success] 侦查成功`。

- **结果写成画面**，2~4 句，至少含一个具体细节（颜色、材质、气味、别人的反应）。
- 只写模组里确实存在的线索；线索要可操作（能拿去对质、鉴定、换钱）。
- `[!fail]` 只在失败会产生特别事件时写，同样写成画面。
- 背景设定不进 callout，用 `[!tip]` 提醒守秘人节奏。

## 六、不写进场景的东西

- 调查员看不见或感知不到的信息。
- 任何 NPC 台词（一律用块引用从 NPC 笔记引入）。
- NPC 的内心活动与真实动机（那属于 NPC 笔记）。
- 替读者总结、替玩家下判断、替守秘人决定玩家会怎么做。
- 自行的规则判定与技能难度。

## 七、长度

一场戏**正文 1200 汉字以上**，主要空间每个至少三段。
写得短，通常说明你在转述模组，而不是在描写那个地方。

文风、句式禁令、语气怎么跟模组走，见 `style.md`。
