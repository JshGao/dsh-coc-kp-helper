# CoC 守秘人备团

你的产出是 **Obsidian 笔记**，不是聊天回答。规范唯一权威是
`references/obsidian-conventions.md`，流程细节在 `references/pipeline.md`。
本文件是主流程 SOP。

## ⚠ 交付质量的第一条：这些笔记要被朗读

守秘人会在跑团桌边**照着念**。所以合格的产出是**有文学性的散文**，不是模组信息的转述。

- **`references/style.md` 是必读**，它的硬指标是：
  场景笔记正文 **≥ 1200 汉字**、叙述段落 **≥ 4 段**、每个主要空间 **≥ 3 段**；NPC 笔记 **≥ 900 汉字**。
- **本次测试暴露的头号失败形态**：把模组原文换个说法抄一遍，或写成条目清单
  （「两把沙发一张茶几」）。这是失败，不是简洁。
- 交付前逐条过 `style.md` 的自检 7 问；**任何一篇不达标就重写，不要交付。**
- 模组原文很短不是理由。恰恰相反，短模组更需要你把那些事实写成具体的画面。

规矩：**模组是大纲，必须遵循；细节由你按人设与时代背景完善**；**不核规则**（不裁定难度、不给骰点建议、不做数值平衡）；**不改用户原件**；
**不覆盖已存在的笔记**（默认跳过并在报告里说明）；`素材/` 与 `调查员/` 只创建不填内容。

## 步骤 0 · 确认可写（不可跳过）

```bash
touch .coc-kp-write-test && rm .coc-kp-write-test && echo WRITABLE
```

失败（`Operation not permitted` 或出现 `[sandbox: file access denied]`）时 **立即停手**，
只输出两条解法，不要重试、不要试图绕过：

1. 以 Obsidian 仓库为工作目录重开会话（这是推荐做法，备团本来就按模组文件夹开会话）；
2. 或在该会话用 `/permissions` 放宽写入。

子 agent 越界的操作会被自动拒绝，重试不会成功。

## 步骤 1 · 落位

向用户确认**模组文件的确切路径**（对话里上传的文件，提示词里会给出一条只读绝对路径；
也可能是用户直接放进仓库的文件）。确认 `ls -l` 能看到它，然后：

- 模组文件名（去扩展名）= 模组名 = 目标文件夹名；
- 用户原件保持原位不动；如果它已经在仓库根就不用管，如果在别处（例如附件目录）
  则**复制**一份到仓库根，`manifest` 记录来源；
- 建骨架：`素材/场景/`、`素材/线索/`、`素材/立绘/` 三个子目录，以及 `角色与势力/调查员/`，
  各放一个 `_README.md` 占位。素材的子目录**先建目录不写内容**，等第八步再填。

## 步骤 2 · 抽取

```bash
python3 <技能目录>/scripts/extract_module.py --src <模组文件> --out <模组名>/.meta/source.txt
```

- 退出码 `0` 正常；`2` 需要先装依赖（按脚本提示在 `.meta/.venv` 里装，不要装到系统 Python）；
  `3` 抽取质量不达标。
- **退出码 3 时限死一条**：把相关页面标成「待人工确认」，**绝不根据封面、目录或常识编造场景内容**。
- 脚本输出的质量指标（可打印字符比、CJK 比、可疑字符数）照抄进 `.meta/manifest.md`。

## 步骤 3 · 大纲与专名

先读 `references/style.md`（写任何一篇之前都要读一次，它是文风的唯一标尺）。
然后只读源文的**骨架层**（页标记、每页首行、疑似场景切换处），不要通读全文。正文是子 agent 的活。
产出两个文件：

- `.meta/outline.md`：场景表（格式见 `pipeline.md`），每行给**行号窗口**，父与子 agent 都按窗口取文；
- `.meta/glossary.md`：专名表：`原名 → 唯一写法`（人名、地名、机构、造物、时代用语）。
  中英混排模组尤其需要；子 agent 一律按这张表用词。

## 步骤 4 · 场景笔记

按 `pipeline.md` 的裁决表选择：父自写 / 子 agent 串行 / 并行 fan-out。

**自包含指令**：子 agent 不加载本技能、不读源文件（窗口小时），直接写它自己那一个目标文件。
每条指令的结构固定：

```
【固定块】欣赏与要求（style.md 的「第一原则 + 四条最常犯的错 + 句式禁令 + 语气表」照抄）
          + 格式硬规范摘要（从 obsidian-conventions.md 摘）
          + 本场戏的组织要点（从 scene-authoring.md 摘）
【可变块】场景名 / 源文窗口（或行号指令）/ 出场 NPC 标准名 / 目标文件绝对路径
```

固定块逐字节相同，可变块放最后。这样前缀缓存能被子 agent 之间复用，
而且每个子 agent 拿到的都是同一套文风与同一段肯定。
子 agent **只回一行状态 + 字数**（`场景/xxx.md: ok, 1840 字`），不要复述正文。

**父自写的场合**：一次只写一篇，写完立刻按 `style.md` 的自检 7 问过一遍，再写下一篇。
交稿前做一次专门的句式复查：数一遍破折号与「不是…是/而是」类对照句，两者都要压到零。

## 步骤 5 · NPC 笔记（一个 NPC 一个子 agent，各自人设）

每个 NPC 交给**独立的子 agent**，并且**先给这个人立人设，再让他写台词**。

1. 父先为该 NPC 写一张**人设卡**（`npc-authoring.md` §1 的六行：他是谁、思维方式和习惯、
   要什么怕什么、信息边界、会怎么应对、说话的腔调）。人设卡由父来写，因为它需要通读全局；
   子 agent 只负责**照这个人设演**，不要让它自己发明性格。**每个人设必须彼此不同**，
   不同之处要落在思维方式与行为习惯上。
2. 派发时读**该 NPC 出场的所有行号窗口**（从 `outline.md` 取并集），窗口内联或给行号。
3. 指令里带齐四样：
   - 人设卡（这个人是谁、要什么、藏什么、怎么说话）；
   - 文风要求（`style.md` 的硬指标与句式禁令）；
   - **对白要求**（`npc-authoring.md`：思维习惯如何决定说法、态度来自处境、动作只在必要处出现）；
   - 出场场景清单与该 NPC 在其中的作用。
4. 每个 NPC 只写自己那一篇，**禁止再委托**，只回一行状态 + 字数。

**为什么分开**：不同 NPC 的思维方式、行为习惯、说法必须彼此不串味。一个子 agent 连写三个人，
三张嘴会写成同一个腔调。分开之后，人设卡就是这条隔离的边界。

NPC 笔记的硬指标是 **≥ 900 汉字**；外貌必须能被直接念出来；对白要成段，动作只在情绪转折处出现。
**每种调查员可能的行为各占一个小标题**，标题里假定好情况，正文给完整发言，台词里不写条件句。
每个小节末尾打块 ID（`^id` 与 `^id-id`），供下一步嵌入。

## 步骤 6 · 把对白嵌进场景

NPC 笔记写完后，回头把场景笔记里该有对白的位置换成块引用：

```
![[<NPC 名>#^id-id]]
```

- 场景里**不留任何 NPC 台词**（模组原文照录的日记、信件、告示除外，那些用 `>` 引用块）。
- 一段对白在多个场景复用时，各处引用**同一个块 ID**，不要复制台词。
- 语法与块 ID 命名见 `obsidian-conventions.md` §3.4。在场景里保留一句环境或动作作为引子，
  然后放引用，读起来才有落点。
- **一段对白一个块 ID，内联在该段行尾**；场景里逐段 `![[NPC#^id]]` 引人。
- 块 ID 只用**一段字母数字**（`^hu01` 或 `^k7f2`），不要连字符、不要范围写法（`^hu01-hu01`）。
- **标记前必须有一个空格**：`「…不见客。」 ^hu01`。漏掉空格，Obsidian 一定报「未找到」。
  标记也不要单独占一行，标记后留一个空行。

## 步骤 7 · 素材（场景与 NPC 全部写完之后才做）

素材部分是**绘图提示词**，不是设定文档。默认引擎 **Chat-GPT Image 2**，每条提示词写英文并配中文翻译。
写法与三类各自的特殊要求见 `references/artifact-authoring.md`。

```
<模组名>/素材/场景/<与场景笔记同名>.md     只画环境，画面里不能有人
<模组名>/素材/线索/<线索名>.md             模组里的笔记/信件/关键物品，透明背景
<模组名>/素材/立绘/<与 NPC 笔记同名>.md    人物立绘，透明背景
```

- 命名与既有笔记**逐字一致**：场景素材对应 `场景/`，立绘对应 `角色与势力/NPC/`。
- **立绘的外观依据只有 NPC 笔记开头的 `- **外貌**：` 那一行**，加上身份、时代、场合；不得矛盾、不得新增设定。
- 线索与立绘必须写 `transparent background`；场景素材必须写 `no people, no figures, no silhouettes`。
- 素材笔记里**只写提示词**，不要写分析或"这张图很重要"之类的话。

## 步骤 8 · 校对

```bash
python3 <技能目录>/scripts/lint_notes.py --module <模组名> --out <模组名>/.meta/lint-report.txt
```

只针对报告里的行做定点 `edit`，**不要重读笔记全文**。FATAL 必须清零；WARN 权衡后处理。

**特殊处理篇幅与文体类 WARN**：`正文过短`、`叙述段落偏少`、`破折号`、`对照句` 四条
是本技能最看重的交付信号。收到时不要加几句凑数，而要**整段重写**：场景补具体事物与调查员视角，NPC 补成大段对白；同时把破折号拆成独立句子，把「不是…是」改成直陈句。
重写后再跑一次 lint 确认四条都清零。

## 步骤 9 · 收尾

1. 写 `总览.md`（格式见 `obsidian-conventions.md`）；
2. 更新 `.meta/manifest.md`：状态、已写文件、跳过项、待人工确认；
3. **逐篇核字数**（`lint-report.txt` 里已有每篇的字数摘要），确认没有低于及格线的笔记；
4. 向用户报告：完成了什么、跳过了什么（及原因）、哪里需要人工确认。
   **不要**把笔记正文贴回对话。

## 子 agent 纪律（父负责）

- 指令里**明确禁止再委托**（孙子 agent 会让成本与一致性失控）。
- 子 agent 只允许 `write` 它自己那一个目标文件；已存在文件默认跳过并报告。
- 每个子 agent 只读自己的窗口；**绝不让多个子 agent 各读一遍整份 `source.txt`**。
- **文学性是硬要求，且子 agent 默认用与父相同的模型**：如果为了省钱把子 agent 切到弱模型，
  产出会明显变干（本技能的第一版就在这点上失败过）。宁可用父自写，也不要让弱模型写正文。
- 单个子 agent 失败或产出不合规时：父改为自写那个文件，并在 `manifest` 记录。
